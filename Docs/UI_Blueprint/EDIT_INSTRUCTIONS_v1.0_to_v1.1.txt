5.4.1 Multi-Vertical Field Configuration Standard

CEO Decision (06 May 2026 — Finding #27): Budget Category is a conditional
field for multi-vertical ERP operation. This section establishes the reference
implementation pattern for all future vertical-specific fields.

REFERENCE IMPLEMENTATION: Budget Category Field

| Aspect | Specification |
|--------|----------------|
| Field Name | Budget Category |
| Data Type | Dropdown (values from Budget Master) |
| Visibility Condition | Display ONLY when: PR Type = Capital (C) AND Division Profile = Paper Mill |
| Mandatory | Yes (when field is visible on Paper Mill screens) |
| Visibility on other divisions | Hidden / Invisible (Spinning Mills, Trading, etc.) |
| Backend Mapping | Division profile × Transaction Type × Field Name → Visibility rule table |
| Frontend Logic | Render conditionally based on logged-in user's division profile |

ARCHITECTURE PATTERN: All future vertical-specific fields must follow this structure:
  1. Visibility rule documented in Blueprint with condition logic
  2. Backend configuration table maps field to [Division + Transaction Type + Field]
  3. Frontend renders conditionally on user's division profile (not hardcoded)
  4. Mandatory flag applies only when field is visible

This pattern ensures consistency across all 4 customer verticals and prevents
field creep on irrelevant transaction types.

NEXT STEP: Sasi to confirm backend configuration table design and review
this pattern before Blueprint v1.1 final sign-off.
