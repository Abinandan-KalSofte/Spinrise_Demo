A Purchase Order raised in M02 (RMI Purchase Order) is the mandatory upstream reference — no goods can be received without an open PO. The buyer selects the category of cotton being received, picks a supplier from the open PO listing, selects the specific PO lines, and enters the weighment details for each vehicle load. The system records the Arrival Number, updates the PO's received quantity balance, marks the supplier lot numbers as received, and triggers the freight amount GL journal posting via the common module. Who uses it: Raw Material Department gate clerks and purchase staff at the Spinning Division. When: Each time a lorry of raw cotton arrives at the mill gate against an open PO. What it produces: An Arrival Number (sequential per financial year per division) that is the mandatory reference for all downstream quality inspection (Lot/Bale Inspection module) and inventory lot creation. Without a valid Arrival record, no quality inspection or stock lot can be created downstream. Downstream consumers: RM Lot/Bale Inspection module (reads ARRNO), RM Lot Creation (reads ARRNO + CONTNO), FA Freight GL journal (FreightAmtPosting), and the daily Arrival Register print (kSP_RM_ARRIVAL). full modify otherwise blocked after lot assignment Replaces CustID block C1 Section 5 — Business Logic and Auto-Fill Rules 5.1 Two-Step Entry Workflow (Add Mode) The Add entry flow has two mandatory preliminary steps before the grid is enabled: Step 1 — Category Selection: User selects a cotton category from rm_cat (e.g. General cotton = &quot;&quot;, Waste = &quot;W&quot;). Category code drives which supplier/PO query runs and whether waste-specific arrival logic applies. Step 2 — Supplier and PO Selection: System shows RM_ArrivalData lookup (unprocessed gate arrivals) or the Contract listing. User selects a supplier, then the ListPO grid is populated with open PO lines (UNION ALL across PackWise and KGSWise, including centralised and import POs). User selects one or more PO lines to receive. Step 3 — Line Entry: Each vehicle load is entered as one row in spdVar. Grid cells auto-calculate weights. Validations fire on LeaveCell. 5.2 ArrivalType Path — PackWise vs KGSWise ArrivalType PackWise (P) KGSWise (K) Balance column checked ordqty − recqty − cancelbales + (ordqty × POWtTolerance%) ordkgs − rcdkgs − cancelkgs + KGS tolerance Grid validation column Ibalqty (Quantity) Igrosswt (Gross Weight) RM_CONT update column on save recqty = recqty + Quantity RCDKGS = RCDKGS + NetWeight RM_DespatchDT update column RVDQTY = RVDQTY + Quantity RVDKGS = RVDKGS + NetWeight 5.3 Net Weight Calculation (Two Paths — Controlled by SeasoncalcReq) Formula Element SeasoncalcReq = Y SeasoncalcReq = N Moisture Weight = (GrossWt − TareWt) × (Moisture% + Trash%) / 100 = (GrossWt − TareWt) × Moisture% / 100 Net Weight = GrossWt − TareWt (moisture weight shown but not deducted) = GrossWt − TareWt − MoistureWt Total Net Wt (Txtfields(28)) = Total GrossWt − Total TareWt = Total GrossWt − Total TareWt − Total MoistureWt 5.4 Gross Weight Auto-Calculation from Truck Weights When both Full Truck Weight and Empty Truck Weight are entered in the grid (Modify mode), the system auto-calculates Gross Weight: GrossWt = FullTruckWt − EmptyTruckWt. In Add mode, user may enter GrossWt directly or use truck weights. 5.5 Supplier Lot Number Validation (SuppLotNoReqArrival = Y) When the user enters a Supplier Lot Number (Iplotno, column 5), the system validates it against the SUPPLIERLOTNOFROM and SUPPLIERLOTNOTO range registered on the PO (RM_CONT). For centralised orders (Prefix='C'), the DIVCODE filter is omitted from the validation query. If the entered lot number is outside the valid range, the field is cleared and focus is returned to the lot number cell. 5.6 PO Balance Check with Tolerance The allowed quantity for each arrival line is: PO balance + (ordqty × POWtTolerance / 100). POWtTolerance is read from RM_PARAM. This allows a configurable over-delivery percentage (e.g. 2% tolerance means 102 bales can be received against a 100-bale PO). If entered quantity exceeds the tolerance-adjusted balance, the quantity is auto-corrected to the maximum allowed and a warning message is shown. 5.7 Modify Guard A standard arrival is eligible for Modify only when ALL conditions are met: No lot/bale details have been entered: RM_ARRIVAL.lotno is NULL for all rows of this arrival No quality inspection has been completed: passed / passdt are NULL Exceptions (controlled by rm_arrival_freight_only_mod_flg=Y, formerly CustID Pallava/Shrigiri): When flag=Y: Even after lot assignment, the arrival may be modified but ONLY the freight amount and lorry number can be changed. All other fields remain locked. This limited modify path writes a separate RM_Trans_Log entry with Trans_Name=&quot;Arrival Freight&quot;. 5.8 Delete Guard An arrival can be deleted only when ALL conditions are met: No lot/bale details entered: lotno IS NULL for all rows No quality inspection completed: passed IS NULL OR passdt IS NULL The financial year is still open: ToValidFinYear() returns True Last arrival date is ≤ pdate (processing date check) [SPINRISE NOTE] SPINRISE delete guard (IST-confirmed 29-Apr-2026): Block arrival deletion when Lot Bale records exist for the ARRNO (RM_LOT WHERE arrno = ARRNO and lottype=’A’ has rows). Do NOT block based on DPDocno population alone — CEO confirmed this logic: once Lot Bale entry exists, Arrival cannot be deleted; if Arrival is deleted before Lot Bale entry is created, there is no downstream impact. The Despatch Plan (DPDocno) link alone is not sufficient grounds for a delete block. 5.9 Inward No. Gate Link When Txtfields(30) (Inward No.) is populated, the save sequence updates the io_materialInward table: SET po_flg='Y' WHERE divcode=[divcode] AND sno=[inwardno] AND date1=[inwarddate]. This closes the gate inward record, confirming that the physical gate-in has been matched to a Purchase Order arrival. 5.10 RM_CONT_SLOTNO Lot Receipt Marking After the main arrival INSERT and CommitTrans, the system: Marks RECFLG='Y' in RM_CONT_SLOTNO for the received slot number Re-reads the remaining unreceived slot numbers Rebuilds the NONRECIEVELOT comma-separated string on RM_CONT This keeps the PO-level unreceived lot list current for gate-in verification 5.11 Arrival Number Generation ARRNO is generated by MaxNo(): SELECT ISNULL(MAX(ARRNO),0)+1 FROM rm_arrival WHERE ARRDATE BETWEEN yfdate AND yldate AND divcode=[Divcode]. This is a MAX+1 pattern without UPDLOCK — a critical race condition defect (CD-1). SPINRISE must replace with SQL Server SEQUENCE object. 5.12 No-Backdate Rule (SPINRISE Design Decision) VB6 controls: last arrival date ≤ pdate check prevents arrivals dated after the processing date. SPINRISE design decision: Arrival date must equal the processing date. No backdated arrival entry is permitted. This is consistent with the M02 PO no-backdate decision (confirmed CEO decision, April 2026). Section 6 — TC Framework This form does not involve TC-based stock or accounting movements. The VB6 code (RMIArrival.frm) contains no write to IN_TRNTAIL or any inventory ledger table. The Arrival Entry records physical receipt in RM_ARRIVAL and updates PO balance in RM_CONT — these are document and balance writes, not TC-triggered stock movements. The only TC reference in the form code is CarJV_TC, which is the Freight GL Journal Voucher TC used by FreightAmtPosting() — this is a financial journal entry for carrier freight, not an inventory stock movement TC.
