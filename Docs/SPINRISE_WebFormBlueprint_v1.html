Design Principles
The five rules that govern every SpinRise screen
①
Single Screen
Every transaction entry form must fit within one screen. No vertical or horizontal scroll. Header + grid + status bar visible simultaneously. Non-negotiable CEO directive.
②
Web-Native
SpinRise does not replicate VB6 visuals. It retains the domain logic and field vocabulary users know, delivered in a modern, clean, browser-native standard.
③
Fewer Keystrokes
Benchmark: does this screen solve ERP 7.4 user pain points with fewer keystrokes, less training time, and fewer errors? Not Oracle Fusion or Zoho.
④
WYSIWYG
What the user sees on screen must match what prints. Same field order, same labels, proportional column widths. Screen and print are always in sync.
⑤
No Abbreviations
"Qty" is Quantity. "Appr. Cost" is Approximate Cost. All labels are full descriptive text in Title Case. All-caps reduces readability on web forms.
⑥
Review Gate
No screen reaches CEO review without: Dev self-check → IST review → TL-IST sign-off → PM clearance. Each reviewer accountable for their scope.

13 — SQL Server 2019 Feature Guidance for Developers

SpinRise targets SQL Server 2019 (15.x). The following features are available and should be used instead of older workarounds. All data access must go through parameterized stored procedures — no raw string SQL, no Entity Framework, no ad-hoc queries.

JSON Support

Use FOR JSON PATH to return structured results from SPs without multi-round-trip joins. Use OPENJSON() to accept JSON payloads for bulk inserts (e.g., multi-line PR insert).

-- Bulk PR lines via JSON TVP
SELECT @LineJson = (
  SELECT LineNo, ItemCode, Qty
  FROM @LineTable
  FOR JSON PATH
);
INSERT INTO PR_Lines
SELECT * FROM OPENJSON(@LineJson)
WITH (LineNo INT, ItemCode NVARCHAR(30), Qty DECIMAL(18,3));
STRING_AGG

Replace FOR XML PATH('') string concatenation with STRING_AGG(). Cleaner, null-safe, and supports WITHIN GROUP (ORDER BY).

-- UOM grouping for KPI strip
SELECT STRING_AGG(
  UOM + ': ' + CAST(SUM(Qty) AS NVARCHAR),
  ' | '
) WITHIN GROUP (ORDER BY UOM)
AS TotalQuantityDisplay
FROM PR_Lines
WHERE PRId = @PRId;
TRIM() — Leading & Trailing

SQL Server 2019 supports TRIM(chars FROM column). Use it to sanitize user input at the SP boundary. Do not rely on application layer trimming alone.

-- Sanitize item code on insert
SET @ItemCode = TRIM(UPPER(@ItemCode));
SET @Remarks  = TRIM(@Remarks);
Approximate Count & Intelligent QP

Use APPROX_COUNT_DISTINCT() for large-table cardinality estimates (e.g., live item count in search). Intelligent Query Processing (IQP) in compat level 150 auto-tunes queries — always run ALTER DATABASE ... COMPATIBILITY_LEVEL = 150.

-- Fast distinct item count for search banner
SELECT APPROX_COUNT_DISTINCT(ItemCode)
FROM Item_Master
WHERE IsActive = 1;
Row-Level Security & Always Encrypted

Phase 2 consideration: RLS filters rows by company/unit automatically. Always Encrypted for PII fields (salary, contact data in HR module M04). Document column encryption strategy before M04 development starts.

Indexing Standards

Every lookup SP that filters by CompanyId + Status must have a composite index. Use filtered indexes for active-only lookups. Columnstore indexes for reporting SPs that aggregate millions of transaction rows (future SPINNOVA layer).

-- Filtered index — active items only
CREATE INDEX IX_Item_Active
ON Item_Master(ItemCode, ItemName)
WHERE IsActive = 1;
SP Naming Convention: All stored procedures follow ksp_<Module>_<Entity>_<Action> pattern (e.g., ksp_RMI_PR_Insert, ksp_RMI_PR_GetById). Use CREATE OR ALTER PROCEDURE — never DROP + CREATE. Every session must update merged.sql alongside the individual SP file.

16 — Performance Standards

SpinRise must remain responsive under concurrent load across spinning mill networks. These standards apply to every module from M01 onwards — document compliance in each module's technical spec.

API Response Time
< 500ms
95th percentile under normal load. Measure at IIS level, not browser level.
Search Debounce
300ms
All live search / typeahead inputs. Prevents request flooding on fast typists.
Lookup Page Size
50 rows
Default page size for all modal pickers. Never load full item master (>10 k rows) at once.
StandardRuleImplementation Pattern
Debounced Search 300ms delay on all typeahead inputs before firing API call Use useDebouncedCallback(fn, 300) from use-debounce library; or setTimeout + clearTimeout in a useEffect
Lazy Loading — Routes All route-level components must be code-split const Page = React.lazy(() => import('./pages/MyPage')) wrapped in <Suspense fallback={<Spin />}>
Lazy Loading — Data List screens load first page on mount; subsequent pages on scroll or pagination action SP accepts @PageNumber and @PageSize params; returns total row count for pagination control
Memoization — Components Wrap pure display components in React.memo() when they receive stable props Grid row components, KPI cards, pipeline steps — all should be memo'd. Verify with React DevTools Profiler.
Memoization — Derived Values Computed totals (Total Value, Total Quantity by UOM) must use useMemo() const totalValue = useMemo(() => lines.reduce(...), [lines]) — never recompute in render body
Stable Callbacks Event handlers passed as props must be wrapped in useCallback() Prevents unnecessary re-renders of child grid rows when parent state updates header fields
Large Dataset Lookups Item Master has >10 k rows — never load all at once SP uses OFFSET / FETCH NEXT pagination + WHERE ItemName LIKE @Search + '%' prefix search (not %@Search% — no leading wildcard on large tables)
Virtualized Grid If item lines exceed 50 rows in a single document, render only visible rows Use react-window FixedSizeList or Ant Design Table virtual scroll for long grids
Skeleton Loading Show skeleton placeholders (not spinner) while initial form data loads Ant Design <Skeleton active /> with paragraph={{ rows: 4 }} while isLoading is true
Optimistic Updates For status toggles and single-field saves, update UI immediately; revert on API error Applicable Phase 2. Phase 1: standard async — await API → update state → show result.
Network environment note: SpinRise is deployed on a factory LAN (172.16.x.x). API roundtrip to IIS is typically <5ms. The 500ms budget is generous — most SPs should complete in <50ms on SQL Server 2019. If an SP exceeds 200ms, add an execution plan review to the code review checklist for that PR.
